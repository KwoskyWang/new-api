# 渠道权重分流（平滑加权轮询 SWRR）

## 概述

当一个模型在**同一分组、同一优先级**下存在多个渠道时，系统会按渠道配置的**权重（Weight）**在这些渠道之间分配请求流量。

分流采用**平滑加权轮询（Smooth Weighted Round-Robin，SWRR）**算法，与 Nginx upstream 加权负载均衡一致：

- 在候选集稳定时，N 次请求内各渠道命中次数**严格符合权重比例**；
- 命中分布**平滑穿插**，而非先把高权重渠道的配额一次性用完。

> 对比旧的「随机加权」：随机方式每次独立抽签，短期（如 10 次）会有运气波动；SWRR 则按精确配额平滑分配。

## 配置位置

默认主题：**渠道列表 → 编辑渠道 → 高级设置（Advanced Settings）→ 路由与覆盖（Routing & Overrides）→ 路由策略（Routing Strategy）**

- **优先级（Priority）**：分层依据。希望多个渠道共同参与权重分流，就把它们的优先级设成**相同值**。
- **权重（Weight）**：分流比例。例如 A=70、B=20、C=10。

## 分层与分流规则

1. **优先级分层**：系统先选出候选中**最高优先级**那一层的渠道。只有该层被耗尽（全部不可用）后，才会降到下一优先级层。
2. **层内权重分流**：在同一优先级层内，按权重用 SWRR 分配流量。

示例（同优先级）：

| 配置 | 实际分流 |
| --- | --- |
| A=70 / B=20 / C=10 | A 70% / B 20% / C 10%（每 10 次精确 7/2/1） |
| A 关闭，剩 B=20 / C=10 | B ≈ 67% / C ≈ 33%（按剩余权重 2:1） |
| 仅剩 B=20 | B 100% |

## 权重为 0 的语义

权重 0 表示「**不参与分流**」：

- **同层存在权重 > 0 的渠道**：权重为 0 的渠道被**完全排除，不会接收任何流量**。
  - 例如同优先级配置 `7 / 2 / 1 / 0 / 0`，则只有前三个渠道参与，流量严格 70% / 20% / 10%，后两个权重 0 的渠道永不被调用。
- **同层所有渠道权重都为 0**：退回**均等分配**，避免整层零流量导致请求无可用渠道。

> 若希望某些渠道作为「备用 / 降级」（平时不用、主渠道全挂时才顶上），应将它们设为**更低的优先级**，而非权重 0。权重 0 仅适合「配置里保留但完全不接量」的场景。

## 存活渠道自动重分配

当某渠道变为不可用时，它会自动从候选集中消失，剩余渠道按各自权重继续分流（即「按存活渠道剩余权重重新分配」）。触发渠道不可用的情形包括：

- 管理员手动关闭 / 禁用渠道；
- 渠道被「自动禁用」机制标记（见下文）。

无需任何手动干预，流量会在候选集变化后立即按新的权重比例分配。

## 与自动禁用机制的配合

本项目的渠道健康检查 / 自动禁用机制（`service/channel.go` 的 `ShouldDisableChannel` / `DisableChannel`）在请求失败后异步判断并禁用故障渠道。需同时满足：

- 全局开关 `AutomaticDisableChannelEnabled` 开启；
- 对应渠道自身的 `AutoBan` 开关开启；
- 命中「渠道级错误」、配置的「自动禁用状态码范围」或「自动禁用关键词」。

渠道一旦被自动禁用，就从权重分流队列中消失，流量按剩余渠道权重重新分配；若开启 `AutomaticEnableChannelEnabled`，恢复后可自动重新加入队列。

## 实现与适用范围

- 主选择路径（内存缓存）：`model/channel_cache.go` 的 `GetRandomSatisfiedChannel` → `selectChannelBySWRR`。
- 主选择路径（非缓存 DB，`MemoryCacheEnabled=false`）：`model/ability.go` 的 `GetChannel`。
- SWRR 核心实现：`model/channel_swrr.go`。
- 模型级故障切换（failover，详见 `docs/model-channel-failover.md`）：`model/channel_failover.go`。该路径按配置保留**随机加权**算法，但权重 0 语义与主路径一致（权重 0 排除，全 0 兜底均匀）。

### 状态存储与多实例

SWRR 的计数器状态保存在**内存**（`model/channel_swrr.go` 的 `globalSWRR`，按 `group + model + priority` 维度分别维护）：

- **单实例**：权重配额完全精确。
- **多实例部署**：每个实例独立计数，整体比例高度接近但非跨实例严格精确。
- **缓存重建**：每次 `InitChannelCache`（渠道缓存定时同步）会清空 SWRR 计数器（`resetSWRRSelectors`），避免引用已变更的渠道 ID；计数会从新周期重新累积。

## 本地自动化验证

在项目根目录运行：

```bash
go test ./model -run 'TestSWRR|TestSelectChannelBySWRR|TestGetModelFailoverChannel' -count=1 -v
```

覆盖：严格配额（7/2/1）、关闭渠道按剩余权重重分配、权重 0 排除、全 0 兜底均匀、以及 failover 路径的权重 0 语义一致性（DB 与内存缓存两种模式）。
