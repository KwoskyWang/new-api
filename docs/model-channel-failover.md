# 模型级渠道故障切换

## 配置

在默认主题的「模型管理 → 新建 / 编辑模型 → 渠道故障切换」中：

- 开启「自动切换故障渠道」。
- 设置「最大渠道切换次数」，范围为 1–10，表单默认值为 2。
- 保存后，当前节点立即生效；其他节点的模型配置缓存最多延迟一分钟更新。

配置保存在模型元数据的 `failover_enabled` 和 `failover_max_retries` 字段中，由现有 GORM 自动迁移添加。现有模型默认关闭，沿用全局 `RetryTimes` 和原有渠道选择逻辑。开启时，模型级次数替代全局重试次数，即使全局为 0 也能切换。

## 行为与边界

- 首次请求仍使用现有分发策略，包括渠道亲和性。
- 遇到允许重试的上游错误后，从**原模型、原实际分组**中选择其他已启用渠道。不切换模型，不跨分组；`auto` 分组也只在首次选定的实际分组内切换。
- 每个请求中，同一渠道最多尝试一次。先尝试剩余渠道中的最高优先级，再按权重选择（权重 0 的渠道按「不参与分流」处理，语义与主路径一致，详见 `docs/channel-weight-routing.md`）；该优先级耗尽后，才降至下一优先级。
- 达到次数上限或没有其他可用渠道时停止；渠道耗尽时保留最后一次上游错误。
- 沿用现有错误重试规则。参数错误、明确禁止重试的错误，以及 504/524 等原本禁止重试的超时，不会因为开启此功能而重试。
- 请求已取消、响应已发送（包括流式输出）、管理员指定渠道，或渠道亲和规则禁止失败重试时，不切换。
- 异步任务的后续操作必须留在原任务渠道，不应用此模型级切换策略。
- 此功能是**请求失败后的切换**，不主动探测健康状态，也不永久禁用故障渠道。后续请求仍使用现有分发和自动禁用机制。

## 管理 API

新建和更新模型的 `/api/models/` 接口支持：

```json
{
  "model_name": "gpt-4o",
  "failover_enabled": true,
  "failover_max_retries": 2
}
```

更新时仍须提供原接口要求的模型 ID 和其他模型信息。旧客户端不提交这两个字段时，保留原有配置；显式提交 `false` 可以关闭。模型名称规则采用与元数据一致的精确、前缀、后缀、包含顺序；精确规则优先，包括显式关闭的精确规则。

## 本地自动化验证

在项目根目录运行：

```bash
go test ./model ./controller -run 'Test.*Failover' -count=1 -v
```

测试使用独立的内存 SQLite 和本地模拟上游，不读取业务数据库或真实模型密钥，不产生调用费用。

`TestRelayFailoverRecoveryHTTP` 会通过真实 HTTP 请求依次执行令牌认证、渠道分发和转发，验证 503 / 连接拒绝后备用渠道返回成功、内存缓存模式、关闭功能、次数上限、400 不重试，以及流式请求在输出前切换。迁移测试还会验证旧模型表新增字段后保留原数据，且已有模型默认关闭切换。
